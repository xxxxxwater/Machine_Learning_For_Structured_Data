# MLSD v0.2.1 — Leakage-Safe Cross-Validation & sklearn Integration

This release builds on the modernized **v0.2.0** research library and focuses on trustworthy ML evaluation, scikit-learn interoperability, and tighter input validation. It includes a new, versioned GitHub Container Registry image. The existing **v0.2.0 release, tag and GHCR image remain unchanged**.

## What's new

- **Cross-validation-ready data view:** `SDataFrame.as_sklearn()` produces an indexable, data-only `FrameSamples` object. It works with scikit-learn `cross_val_score` and compatible tools without treating the original `SDataFrame.fit()` container as a model estimator.
- **Safe row and column selection:** Added independent `take()` selections, position-based `iloc` access, consistent `shape` and feature-name output. Selections do not alias nested training rows.
- **Actual event-time purging:** New `PurgedEventTimeSeriesSplit` drops training samples with forward-label end times overlapping the start of a validation fold, in addition to any configured row-based gap. The earlier `PurgedWalkForwardSplit` remains available.
- **Strict schema validation:** Train/test frames must preserve ordered column names and per-column data types. Misaligned pandas target indexes now produce clear errors instead of pairing the wrong labels and observations.
- **Atomic resampling:** If a row cannot be resampled, its siblings are not left partly changed.
- **Quality gates:** Expanded regression and integration coverage for model-selection protocols, dtype drift, event overlap, and index integrity. CI also installs and tests optional B-spline/LOWESS backends, checks Ruff correctness, and builds distributions.

## Installation

Install the downloadable Python distribution or from this immutable source tag:

```bash
python -m pip install https://github.com/xxxxxwater/Machine_Learning_For_Structured_Data/archive/refs/tags/v0.2.1.tar.gz
```

For optional feature extractors:

```bash
git clone https://github.com/xxxxxwater/Machine_Learning_For_Structured_Data.git
cd Machine_Learning_For_Structured_Data
git checkout v0.2.1
python -m pip install -e '.[tsfresh,spline,lowess]'
```

### GHCR container package

```bash
docker pull ghcr.io/xxxxxwater/mlsd-structured-data:v0.2.1
docker run --rm ghcr.io/xxxxxwater/mlsd-structured-data:v0.2.1
```

The `latest` tag is also updated to v0.2.1. The exact `v0.2.0` tag is retained. GHCR package visibility is managed separately from the repository; private packages require GitHub Packages authentication.

## Usage: leak-aware evaluation

```python
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from MLSD import activeTrans

model = make_pipeline(activeTrans(), LogisticRegression(max_iter=500))
# "frame" is an existing SDataFrame, "y" has one label per sample:
scores = cross_val_score(model, frame.as_sklearn(), y, cv=3)
```

For chronological labels with irregular future horizons use `PurgedEventTimeSeriesSplit`, supplying a pandas Series of actual label-end timestamps aligned with the frame's unique ordered DatetimeIndex. [Full guide](https://github.com/xxxxxwater/Machine_Learning_For_Structured_Data/blob/v0.2.1/docs/cross-validation.md).

## Validation and known limitations

The v0.2.1 development candidate passed the GitHub CI matrix on **Python 3.10, 3.11, 3.12 and 3.13**, including **41 passing core tests (2 optional-backend skips)** and a separate **6 passing optional-backend tests** with Ruff checks. The release workflow independently reruns these gates before publishing assets and the GHCR image. Minor NumPy/Pandas future-deprecation warnings in some event-time tests are not API errors.

This project remains a research-oriented structured feature toolkit, not a certified production forecasting platform. Event-time purging prevents target-horizon overlap but **does not** eliminate leakage from noncausal features, data revisions or late-arriving external data. Original thesis notebooks, archived legacy pyFDA utilities, and historical benchmark-equivalence have not been fully revalidated.
